# نصب SamaLine روی cPanel

## قبل از شروع — یک نکته‌ی مهم

SamaLine یک اپ **Node.js** است، نه PHP. این نصاب خودش سامانه را اجرا نمی‌کند؛
کارش این است که محیط را بشناسد، Node را پیدا کند، وابستگی‌ها را نصب و build
کند، تنظیمات را بسازد و سرویس را بالا بیاورد — همه از داخل مرورگر و بدون SSH.

یعنی **هاست شما باید Node.js نسخه ۲۰ یا بالاتر داشته باشد.** روی cPanel این
یعنی بخش «Setup Node.js App» فعال باشد. اگر هاست فقط PHP می‌دهد، هیچ نصابی
نمی‌تواند این را حل کند؛ باید هاست را عوض کنید یا از سرور مجازی استفاده کنید.

## مرحله‌ی ۱ — ساخت اپ Node در cPanel

۱. وارد cPanel شوید و **Setup Node.js App** را باز کنید.
۲. **Create Application** بزنید:

| فیلد | مقدار |
| --- | --- |
| Node.js version | ۲۰ یا بالاتر |
| Application mode | Production |
| Application root | `samaline` |
| Application URL | دامنه یا زیردامنه‌ی مورد نظر |
| Application startup file | `app.js` |

۳. **Create** بزنید. cPanel یک پوشه‌ی `samaline` و یک مفسر Node اختصاصی
   می‌سازد. مسیر آن مفسر را یادداشت کنید — چیزی شبیه:
   `/home/USERNAME/nodevenv/samaline/20/bin/node`

> `app.js` همراه فایل‌های پروژه می‌آید، پس می‌توانید همین حالا انتخابش
> کنید. تا وقتی build تمام نشده، Passenger خطا می‌دهد؛ پس از نصب یک بار
> **Restart** بزنید.
>
> **این فایل را با `backend/dist/main.js` عوض نکنید.** مسیر پایگاه‌داده
> نسبت به پوشه‌ی کاری حساب می‌شود و Passenger برنامه را از ریشه اجرا
> می‌کند؛ `app.js` پوشه‌ی کاری را درست می‌کند. بدون آن، یک پایگاه‌داده‌ی
> خالی در ریشه ساخته می‌شود و داده‌ی واقعی جای دیگری می‌ماند.

## مرحله‌ی ۲ — آپلود فایل‌ها

فایل `samaline.zip` را در **File Manager** داخل پوشه‌ی `samaline` آپلود و
Extract کنید. ساختار باید این‌طور شود:

```
samaline/
  backend/
  panel/
  form-renderer/
  installer/
  scripts/
```

## مرحله‌ی ۳ — اجرای نصاب

در مرورگر باز کنید:

```
https://YOUR-DOMAIN/installer/install.php
```

صفحه اول محیط را بررسی می‌کند:

- موارد **قرمز** یعنی بدون حل شدنشان نصب ممکن نیست.
- موارد **نارنجی** هشدارند و نصب را متوقف نمی‌کنند.

اگر Node را پیدا نکرد، مسیری که در مرحله‌ی ۱ یادداشت کردید را در فیلد
«مسیر Node» بگذارید و دوباره بررسی کنید.

«نشانی عمومی» را هم پر کنید (مثلا `https://survey.example.com`). این نشانی
در تنظیمات ذخیره می‌شود و **وبهوک ربات تلگرام بدون آن ثبت نمی‌شود** — یعنی
فرمان‌های ربات کار نمی‌کنند.

سپس **شروع نصب** را بزنید. نصب چند دقیقه طول می‌کشد و لاگش زنده نمایش داده
می‌شود. **بستن صفحه نصب را متوقف نمی‌کند** — نصب در پس‌زمینه ادامه دارد و با
باز کردن دوباره‌ی صفحه، ادامه‌ی لاگ را می‌بینید.

روی هاست دارای Passenger (همان cPanel)، نصاب سامانه را **اجرا نمی‌کند**؛ فقط
می‌سازد و آماده می‌کند. اجرا کار خود cPanel است: به «Setup Node.js App»
برگردید و **Restart** بزنید. راه‌انداختن پروسه‌ی جدا کنار Passenger یعنی دو
پروسه سر یک پورت دعوا کنند، و پروسه‌ی بی‌صاحب روی هاست اشتراکی به‌هرحال
کشته می‌شود.

## مرحله‌ی ۴ — پس از نصب

۱. پوشه‌ی `installer` را **پاک کنید**. تا وقتی روی هاست باشد، هر کسی که
   نشانی‌اش را بداند می‌تواند بازش کند.
۲. به `https://YOUR-DOMAIN/panel` بروید و از «ثبت‌نام» اولین حساب را بسازید.
۳. برای دسترسی به «تنظیمات سامانه» (نوار پایین فرم‌ها)، از ترمینال cPanel:

```bash
cd ~/samaline/backend && npm run superadmin -- your@email.com
```

## اگر مشکلی پیش آمد

| مشکل | راه‌حل |
| --- | --- |
| «اجرای دستور: مسدود» | از پشتیبانی هاست بخواهید `shell_exec` یا `proc_open` را برای این حساب باز کنند. بدون این، نصاب کاری نمی‌تواند بکند. |
| «Node.js: پیدا نشد» | اپ Node را در cPanel بسازید (مرحله‌ی ۱) و مسیر مفسر را دستی بدهید. |
| «فضای دیسک» هشدار داد | نصب حدود ۸۰۰ مگابایت فضای موقت می‌خواهد. پس از نصب، وابستگی‌های توسعه خودکار پاک می‌شوند. |
| نصب وسط کار متوقف شد | لاگ را در همان صفحه ببینید. معمولا کمبود حافظه یا دیسک است. |
| سامانه بالا آمد ولی صفحه سفید است | مطمئن شوید Application startup file روی `app.js` تنظیم است. |
| «JavaScript heap out of memory» وسط build | حافظه‌ی هاست کم است. نصاب سقف ۵۱۲ مگابایت می‌گذارد؛ اگر باز هم افتاد، از پشتیبانی هاست حافظه‌ی بیشتر بخواهید. |
| سامانه خالی است ولی قبلا داده داشت | احتمالا startup file روی `backend/dist/main.js` است. برش گردانید به `app.js`؛ داده‌ی شما در `backend/data/` سالم است. |
| ربات تلگرام به فرمان‌ها جواب نمی‌دهد | `PUBLIC_URL` در `backend/.env` باید نشانی واقعی سایت باشد. پس از اصلاح، توکن ربات را در پنل دوباره ذخیره کنید تا وبهوک ثبت شود. |

## داده‌ها و پشتیبان‌گیری

همه‌چیز در `backend/data/` است:

- `samaline.sqlite` — پایگاه‌داده
- `uploads/` — لوگوهای آپلودشده

برای پشتیبان‌گیری همین یک پوشه کافی است. فایل `backend/.env` کلیدهای رمزنگاری
را دارد؛ آن را هم نگه دارید، چون **عوض شدنش یعنی همه‌ی توکن‌های صادرشده و
داده‌ی رمزشده از کار می‌افتد**.
